# Simverse World 词语表

这是一张“难词翻译表”。

第一次看项目的人，可以从这里查词。
每个词都有一句白话和一个项目例子。

## 游戏里的词

### 玩家（Player）

- 白话：正在玩游戏的人。
- 例子：玩家登录后，可以控制自己的角色。

### 居民（Resident）

- 白话：生活在小镇里的角色。
- 例子：居民会走路、工作、聊天和记事情。

### NPC

- 白话：由程序控制的居民，不是真人玩家。
- 例子：NPC 会自己决定去哪里和做什么。

### Agent

- 白话：能接收信息，并自己采取行动的程序角色。
- 例子：居民 Agent 会观察四周，再选择行动。

### Onboarding

- 白话：第一次进入游戏时的新手引导。
- 例子：新玩家会先选择或创建一位居民。

### Forge（炼化居民）

- 白话：制作新居民的工具。
- 例子：玩家可以填写资料，做出一位新角色。

### Soul Coin（灵魂币）

- 白话：小镇里使用的钱。
- 例子：玩家可以买东西，也能获得灵魂币奖励。

### 记忆

- 白话：居民保存下来的经历。
- 例子：居民会记得一次聊天和双方的关系。

### 人格

- 白话：居民比较稳定的性格特点。
- 例子：不同人格会影响居民的作息和说话方式。

### 实验楼（Lab）

- 白话：用来发布研究任务的特殊功能区。
- 例子：目前线上只保留参观，执行功能已经关闭。

### Hosted Agent（托管 Agent）

- 白话：由服务器长期照看的外部 Agent。
- 例子：管理员关掉后台页面后，它仍可继续在线。

## 人工智能里的词

### AI（人工智能）

- 白话：让电脑完成一些像人一样的任务。
- 例子：AI 帮助居民理解文字并作出回答。

### LLM（大语言模型）

- 白话：一种会读写文字的 AI 大脑。
- 例子：居民聊天时，后端会请求 LLM 生成回答。

### Prompt（提示词）

- 白话：发给 AI 的任务说明。
- 例子：提示词会告诉 AI 居民的身份和当前场景。

### Embedding（向量）

- 白话：把一段文字变成一串可比较的数字。
- 例子：系统用向量寻找意思相近的旧记忆。

## 程序里的词

### 前端（Frontend）

- 白话：玩家在浏览器里看到和点击的部分。
- 例子：地图、按钮和聊天窗口都属于前端。

### 后端（Backend）

- 白话：在服务器上处理规则和数据的部分。
- 例子：登录、扣钱和保存记忆都由后端完成。

### API（程序接口）

- 白话：两个程序互相传话的门。
- 例子：前端通过 API 向后端读取居民列表。

### REST API

- 白话：一问一答式的程序接口。
- 例子：前端请求一次，后端返回一次市场货单。

### WebSocket

- 白话：一直保持连接的实时传话通道。
- 例子：居民移动后，服务器马上通知在线玩家。

### 路由（Route）

- 白话：网页或接口的地址规则。
- 例子：`/play` 是游戏地图页面的地址。

### 数据库（Database）

- 白话：长期保存资料的电子仓库。
- 例子：用户、居民、记忆和交易都存在数据库里。

### PostgreSQL

- 白话：本项目正式环境使用的数据库软件。
- 例子：生产服务器用它保存小镇的长期资料。

### pgvector

- 白话：让 PostgreSQL 能保存和查找文字向量的工具。
- 例子：它帮助系统找回意思相近的居民记忆。

### Redis

- 白话：速度很快的临时记事本和消息站。
- 例子：它保存短期状态，也传递实时消息。

### Worker（后台工人）

- 白话：不显示页面，只在后台持续工作的程序。
- 例子：Agent Worker 会让居民继续生活。

### Bootstrap（启动准备）

- 白话：正式开机前先做的准备工作。
- 例子：生产 Bootstrap 会先升级数据库结构。

### Migration（数据库迁移）

- 白话：按顺序改变数据库结构的步骤。
- 例子：增加一张新表时，要先运行对应迁移。

### Docker

- 白话：把程序和运行环境装进标准盒子的工具。
- 例子：数据库、Redis 和 API 都可以放进 Docker。

### Docker Compose

- 白话：一次管理多个 Docker 盒子的工具。
- 例子：一条命令可以启动数据库和 Redis。

### Profile（服务分组）

- 白话：只在需要时才打开的一组服务。
- 例子：实验楼服务放在单独的 Lab Profile 中。

### 功能开关（Feature Flag）

- 白话：不用改代码，就能开关功能的按钮。
- 例子：`LAB_ENABLED=false` 表示实验楼执行关闭。

### OAuth

- 白话：借助其他网站确认登录身份的方法。
- 例子：玩家可以使用 GitHub 或 LinuxDo 登录。

### JWT（登录凭证）

- 白话：登录成功后拿到的一张临时通行证。
- 例子：前端带着它请求需要登录的接口。

## 运维里的词

### 开发环境

- 白话：开发者在自己电脑上使用的测试环境。
- 例子：本地可以用 SQLite 快速启动项目。

### 生产环境

- 白话：真正给用户使用的线上环境。
- 例子：`simverse.world` 连接的是生产环境。

### Staging（上线前环境）

- 白话：正式上线前用来试运行的环境。
- 例子：危险的新功能应先在这里验证。

### 健康检查（Health Check）

- 白话：询问服务是否还能正常工作的检查。
- 例子：访问 `/health`，正常时会返回成功状态。

### 日志（Log）

- 白话：程序运行时写下的工作记录。
- 例子：服务出错时，维护者先查看日志。

### 回滚（Rollback）

- 白话：新版本出问题后，退回旧版本。
- 例子：部署前保留旧镜像，失败时可以恢复。

### Runbook（操作手册）

- 白话：处理一次具体运维任务的步骤清单。
- 例子：上线前，维护者要按 Runbook 逐项检查。

### vm212

- 白话：当前生产后端服务器的 SSH 名称。
- 例子：维护者使用 `ssh vm212` 连接这台服务器。

### Archive（归档）

- 白话：保存旧资料的只读档案柜。
- 例子：归档能解释历史，但不代表当前状态。
