## 值得注意的问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | M1–M6 整批代码还没提交 git,和修复批混在工作树里 | 误操作可能丢失几周的工作 | 最优先:按已写好的方案切分提交 |
| 2 | 本地、GitHub、生产服务器三边代码不同步 | 后续合并会有冲突,从 GitHub 部署会导致生产降级 | 部署永远以生产分支为基线,尽快三边对齐 |
| 3 | NPC 看不懂玩家发的图片(生产已确认) | 多模态是对外宣传的核心卖点 | 修复前不宣称"全功能可用" |
| 4 | 内置居民缺人格数据 → NPC 投票总偏向第一个选项 | 选举和议案结果失真 | 上线前补齐(工作量小) |
| 5 | 玩家角色会被当成 NPC 自动跑,烧预算且没有家 | 每多一个玩家成本+1 份,行为也奇怪 | 需要产品决策:算特性还是排除 |
| 6 | 预算熔断在计量故障时会"默默失效" | 极端情况下成本失控无告警 | burn-in 期间人工盯,后续加告警 |
| 7 | 世界每天只"活"约半小时,其余时间全员待机 | 玩家大部分时间看到静止的小镇 | 就是阶段 0 的决策 ③,尽快定 |
| 8 | 单服务器架构假设(不能开多实例) | 限制扩容上限,重启丢状态 | 人口过 40 前需要正视 |
| 9 | 前端在 Node 25 下打不了包 | 反复浪费排查时间 | 团队统一锁定 Node 22 |
| 10 | 夜间任务(日报/梦境/选举)错过窗口不补跑 | 重启赶上时间点会静默丢一晚内容 | 排期加补跑机制 |
