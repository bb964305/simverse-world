# 外来商队 V1 设计规格

状态：V1 已实现并通过自动化测试；生产生命周期由环境开关独立控制。
工作代号：`indigo_caravan`（靛篷商队）。

## 设计目标

集市日开始后，商队从小镇南侧入口进入，沿固定安全路线前往独立的集市大厅；抵达后将同一辆篷车在大厅装卸区展开为摊位并开始交易；集市日结束后收摊，沿反向路线退出小镇。玩家在任何时间进入游戏，都应看到与服务端状态一致的商队位置和形态。

V1 不是普通 `Resident`，也不占居民名册。它是一项由集市世界事件驱动的临时世界实体。

## 形象定案

商队由三个视觉部分组成：

1. 一匹敦实的浅褐色矮脚驮马，负责形成清楚的行进方向。
2. 一辆紧凑的双轮旧木篷车，使用靛青色篷布、黄铜铃铛和绳结；侧板可翻下成为售货柜台。
3. 一名外来领队商人，宽檐帽、暗青旅行外套、赭黄色围巾和小挎包；友好、干练，不携带武器。

货物只使用少量可读剪影：茶罐、布卷、小木箱和旅行杂货。不能把车装饰成豪华马车，也不能使用现代机动车或大型旗帜。

## 游戏资产合同

概念图只定义造型，不直接作为运行时贴图。正式透明资产已放在独立目录，没有占用固定 25 槽的 `agents/` 目录：

```text
frontend/public/assets/village/caravan/
├── merchant/
│   ├── texture.png          # 96×128，32×32/帧，3列×4方向
│   ├── portrait.png         # 256×256，可选
│   ├── atlas.json
│   └── generation-provenance.json
├── convoy/
│   ├── texture.png          # 192×256，64×64/帧，3列×4方向
│   ├── atlas.json
│   └── generation-provenance.json
└── stall/
    ├── texture.png          # 64×64 静态展开态，可追加2帧微动画
    └── generation-provenance.json
```

商人沿用现有居民 atlas 合同：行顺序为 `down / left / right / up`，三帧组成 `左脚 → 中立 → 右脚 → 中立` 的四拍步行循环，脚线固定在帧内 `y=30`。

马与车在 V1 合并成一个 `64×64` convoy sprite。逻辑占地始终为一个 tile；可见剪影最长不超过约 60px，即接近两个 32px tile。不要根据概念图制作三格或更长的车辆。商人作为独立 sprite 跟随在车侧后方。

所有正式 PNG 都是 RGBA 真透明、1-bit alpha（只含 0/255）、包含透明色在内不超过 32 色；provenance 记录提示词合同、内置生成器、处理流程、尺寸、字节数与 SHA-256。提交资产由后端 Pillow 测试和前端 Phaser atlas 合同测试共同验收。

## 运行时状态

```text
scheduled
  -> waiting       集市尚未开始，在地图外等待
  -> inbound       从 town_entrance 进入
  -> trading       到达 market_hall，篷车切换为 stall
  -> outbound      集市结束，摊位收起并反向离镇
  -> departed      离开地图，实体隐藏
```

异常或被取消的集市进入 `cancelled`。集市结束时若商队仍在入场，直接切换到安全退场流程，不允许瞬移到大厅后再离开。

### 触发时机

- 集市世界事件 `phase=start`：创建或恢复 visit，广播 `inbound`。
- 抵达停车点：只在此时执行现有商队经济结算，随后进入 `trading`。
- 集市世界事件 `phase=end`：停止新交易，关闭剩余进口货，进入 `outbound`。
- 抵达南门外：进入 `departed`，前端销毁临时实体。

同一 `world_event_id` 只能对应一次 visit。摊位费、作品收购、进口货补货和单件收购都必须拥有独立幂等键；重启后从已持久化的 phase、路线和服务端时间恢复，不能重复收费或收购。

## 路线与移动

- 出生锚点：小镇南门外 staging tile；停车锚点：集市大厅内专用 loading tile。两者都从真实 collision-open tiles 中确定性选择，不使用逻辑强制可达点冒充物理道路。
- `caravan_route.py` 在构建/测试时生成并审计固定路线，验证每一步都是四邻接、铺装或室内地坪可见、物理可走且可从南门连续到达大厅；当前地图结果为 41 个 tile、1 次转向。
- clearance 报告明确区分 `1×1` 逻辑锚点与 64px 可见外扩。权威地图现已绘制五格宽大道、两格无树肩带和五格宽大厅装卸口，连续两格宽体审计为通过；运行时仍以单格中心线作为服务端锚点，车体外扩只会在最南侧两个离屏 staging 格接近地图边界。
- 路线只在生命周期需要时惰性解析；功能暗闸关闭或路线异常时不得拖垮 API 启动。
- 服务端持久化路线与 `motion_started_at/motion_ends_at`；WebSocket 发送带版本号的完整 `caravan_state`。前端按服务端时间插值，不逐格写数据库。
- 客户端初次加载或断线重连时通过 `GET /caravans/current` 收敛；WebSocket 只负责实时投影。
- convoy 建议 6fps，merchant 6–8fps。每次方向改变时切换 atlas 行，禁止保持正面静态滑行。

## 玩家可见反馈

| 阶段 | 地图表现 | 横幅文案 |
|---|---|---|
| inbound | 南门出现马、篷车和商人，沿道路进镇 | 远方商队正从南门进镇 |
| trading | 篷车在集市大厅装卸区展开柜台，镇民可在摊位间停留 | 商队已在集市大厅开摊 |
| outbound | 柜台收起，车队沿原路线离开 | 集市散场，商队正在离镇 |
| departed | 临时实体消失 | 回到普通集市结束状态 |

商队进出场只是一条队伍：一辆车、一匹马、一名商人。V1 不增加护卫或第二辆车，以免形成编队、避障和道路占宽问题。

## 交互边界

- 保留现有经济规则：商队收购居民作品、缴纳摊位费，并带来茶叶、小玩意和花布。
- V1 商人可显示名称和一句到访气泡；是否向玩家开放进口货购买属于后续产品决策，本设计不擅自改变现有“进口货只供 NPC 消费”的规则。
- 动态页需要为 `caravan_purchase` 和进口货 `npc_purchase` 增加中文图标与摘要，避免继续显示原始事件 kind。

## 验收标准

1. 集市开始、结束各触发一次进出场；刷新、重连或 worker 重启不重复结算。
2. 商队从入口连续移动至停车点，没有瞬移、静态滑行、穿墙或倒着移动。
3. 商队进入 `trading` 前不发生收购；进入 `outbound` 后不再成交。
4. 晚加入的客户端看到与服务端时间一致的位置，误差不超过一个 tile。
5. 商人和车辆在 1×、1.25× 与小地图缩放下仍可辨识；正式资产通过尺寸、调色板、透明边缘和 provenance 检查。
6. 集市结束后临时实体、动画、WebSocket 监听器和未售进口货均正确清理。

## 实现与开闸

- 服务端：`caravan_visits` 持久化 `scheduled → waiting → inbound → trading → outbound → departed/cancelled`；`world_event_id` 唯一；CAS version、可过期 lease 和逐项 purchase 唯一键负责重启/多 worker 幂等。
- 协议：`GET /caravans/current` 与 WebSocket `caravan_state` 共用同一份 full snapshot；未来 scheduled 记录不会遮蔽当前可见到访。
- 客户端：按 `server_time + motion path` 做逐段插值，乱序/重复 version 被丢弃；初载、认证重连和慢 GET 都经过同一 reducer，终态销毁临时容器。
- 财务：只有到达 `trading` 后才结算摊位费、作品收购与进口货；退场前撤下本次 visit 的剩余进口货。
- 配置：需要同时启用既有 NPC 经济/商队准入和新的 `CARAVAN_LIFECYCLE_ENABLED`；新生命周期默认关闭，迁移、worker 和视觉联调完成前不随代码发布自动开闸。

## 生成记录

本轮使用 Codex 内置 ImageGen（默认内置模式）生成两张概念图，以及商人身份锚、商人三方向步行条、马车身份锚、马车三方向行进条和展开摊位原图。提示词统一要求“浅褐矮脚马 + 靛青双轮篷车 + 暗青外套商人”、无文字/标志/现代载具，并使用纯 `#FF00FF` 色键背景。正式资产先由技能自带 `remove_chroma_key.py` 去底与去溢色，再由确定性处理器以 nearest-neighbor 对齐基线、镜像右向、限制为 31 个不透明色加透明色。逐资产完整提示词合同和源图标识记录在各自的 `generation-provenance.json`。
